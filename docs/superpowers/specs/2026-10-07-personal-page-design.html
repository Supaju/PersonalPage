Personal Portfolio Site - Design Spec

2026-10-07 · Status: draft for review

1. Purpose

A personal site that advertises the owner as a backend/systems/cloud and full-stack developer. Audiences: employers and interviewers (primary), plus prospective freelance clients (secondary, served by the general portfolio, with no dedicated freelance section). The site is itself a portfolio piece and will be shared in interviews.

Success: a visitor sees who the owner is, what they have built, and how to reach them within one screen of scrolling.

2. Decisions

AreaDecision
StackAstro, static output, no client framework. Content as Markdown via content collections.
LayoutHybrid: single-page home plus detail pages for projects and case studies.
StyleClean minimal. Off-white/white, blue accent, large type, whitespace.
ExtrasLight/dark toggle (follows system, manual override), subtle animations (respect prefers-reduced-motion), project filter by tech.
ContactEmail (mailto:), LinkedIn, GitHub. No form.
HostingFree static host on a free subdomain (e.g. GitHub Pages or Cloudflare Pages). Custom domain later.
ContentPlaceholders (name, tagline, sample projects/case studies). Owner fills in later.

3. Pages

  • / Home: hero (name, tagline, Email/GitHub/LinkedIn/Résumé buttons), featured projects with tech filter, work summary, about blurb, contact footer.
  • /projects/<slug> Project detail: summary, role, tech list, what was hard, live demo link, GitHub link.
  • /work/<slug> Anonymized case study: problem, role, tech, approach, impact. No employer secrets.
  • About and résumé: a section on Home with a PDF download (public/resume.pdf).

4. Structure

src/
  content/
    projects/*.md     frontmatter: title, summary, tech[], demo?, repo?, featured, order
    work/*.md         frontmatter: title, role, period, tech[], summary
  components/         Header, Hero, ProjectCard, TechFilter, ThemeToggle, Footer
  layouts/Base.astro  html shell, meta/OG tags, theme init
  pages/
    index.astro
    projects/[slug].astro
    work/[slug].astro
  styles/global.css   CSS variables for light/dark, accent, type scale
public/resume.pdf, favicon

5. Behavior

  • Theme: CSS variables; inline script in <head> sets data-theme from localStorage or system preference to avoid flash. Toggle persists the choice.
  • Tech filter: a few lines of vanilla JS toggling hidden on cards by data-tech. Without JS all cards show.
  • Animations: CSS-only fade/translate on scroll-in and hover, disabled under reduced motion.
  • Content errors: Astro content-collection schemas (zod) fail the build on missing or invalid frontmatter.

6. Non-functional

  • Responsive from phone width; semantic HTML, visible focus states, AA contrast in both themes, alt text on images.
  • Target Lighthouse 95+ in all categories; no third-party scripts.
  • SEO basics: title, description, Open Graph tags, sitemap.

7. Testing

Verification is astro build (schema checks) plus a manual pass on Home and one detail page in light/dark at phone and desktop widths. No test framework; revisit if interactive logic grows.

8. Out of scope

Blog, contact form, CMS, freelance services page, analytics, i18n, embedded interactive demos. Each can be added later without restructuring.
